# 版本记录与迭代

## 怎么迭代这个技能

技能文件本身不会自动更新。迭代靠一个固定动作：

**每次出图发现新的翻车点，就把「症状 + 根因 + 补救句」三件套告诉 Claude，让它重新打包一版新的 .skill 文件。**

一句话就够：

> 新发现：[症状]，原因是 [根因]，补 [补救句] 有效。更新 refimg-prompt-cn 技能。

Claude 会把它并进 `troubleshooting.md` 的对应分类，版本号 +0.0.1，重新打包发给你。

判断一条发现值不值得进技能，看两点：**能复现**，且**不是这一次造型独有的**。只出现过一次的偶发问题不要写进去，会污染表格。

## 版本历史

### 1.3.0

新增 `scripts/face_privacy_tool.py`：裁头/遮脸自动化脚本，用 OpenCV 的人脸检测自动定位五官区域，不用再每次手动估算裁剪坐标。三个子命令：`crophead`（裁掉整个头，服装参考图首选）、`maskface`（只遮五官保留发冠头饰，复杂造型首选）、`detect`（预览检测框，不生成文件）。支持批量处理整个文件夹，检测失败时可用 `--bbox` 手动指定。

踩坑记录：给检测器做直方图均衡化（equalizeHist）在高调柔光的古风写真上反而会把框带偏到饰品上；改成多个 scaleFactor 汇总候选框、取面积最大的那个，稳定性明显更好。`crophead` 对贴脸特写类参考图效果差——脸占满画面时默认裁切比例会把衣服一起裁掉，这种情况应改用 `maskface`。

### 1.2.0

新增「只有人物图的氛围感创作」模式，以及配套的配方库 `mood-recipes.md`（10 组已验证的光线+场景+色调+情绪组合）。

核心结论：氛围感的排序是 **光 > 不给正脸 > 前景遮挡 > 留白**，场景本身反而排在后面。前景遮挡（树叶/纱帘/玻璃/栏杆横穿画面）是「像摄影作品」和「像自拍」的分界线。

新翻车点：**只有一张人脸参考时，脸比有 C 图时更容易漂**——因为没有别的信息分散注意力，模型的创作自由全用在脸上。对策是提示词里绝对不出现任何对脸的褒义形容词（「精致」「美丽」「高级脸」），那些词等同于重画许可。

### 1.1.0

新增「场景替换（换背景）」这一类任务。

核心结论：**换背景的难点是光，不是背景。**失败几乎都不是背景画错了，而是人物还带着原场景的光——白天冷光的人贴进夜景，一眼就是抠图。所以必须写独立的【光线重打】段，明确新主光的来源方向、人物边缘接受什么色温的环境光、以及「绝不能出现 X 光的人配 Y 光的背景」。

配套发现：换背景时「必须保持不变」的清单要逐项点名到妆容浓度、头饰数量、发髻形状这个颗粒度。只写「人物不变」，模型会顺手重绘妆造。

### 1.0.0

首个版本。整理自一次完整的实战：现代街拍复刻 → 古风妆造系列 → 复杂头饰造型的换脸修正。

已验证的核心结论：

- 参考图职责分离（A 脸 / B 景 / C 妆造）+ 显式优先级，是整套方法的地基
- **脸被 C 图污染是最高频的失败**，文字约束无效，只能靠裁头 / 遮脸 / 两步法
- 提示词越长，末尾段落权重越低；分镜必须前置
- 否定式约束比正面描述有效得多
- 「人显矮」是机位 + 腰线 + 发型体量三者叠加，不是模型的锅
- 光线一致性那一段是「像不像真照片」的分水岭
- 批量出图 = 同一提示词跑 N 个种子，无法指定每张的姿势
- 服装参考图的最佳来源是电商平铺图，天然无脸无水印

## 待验证

以下是有理由怀疑成立、但还没有跑够样本的假设。验证后再升级为正式条目。

- 把 A 图重复传入两次是否能提高脸的权重
- 遮脸时用高斯模糊 vs 纯色块，哪种对模型的「忽略」信号更强
- 服装参考图给 4 张（正面 / 背面 / 细节 / 平铺）是否比 2 张明显更准
- 分镜前置的收益在不同模型上是否一致（目前只在 ChatGPT 图像上验证过）
- 「参考图 D = 连续性基准」这个做法对第 3、4 张的实际增益有多大
