# C 语言新手的常见错误模型

每条包含：**错误的心智模型** → **诊断问题**（能判对错的）→ **纠正路径**。

诊断问题的用法：怀疑学生有这个错误模型时，直接问，不要先解释。他答错了，你才知道该讲什么；他答对了，跳过这一条省时间。

---

## 1. 赋值方向

**错误模型**：`=` 是数学里的等号，两边是"相等"的关系，写哪边都行。

典型症状：`num = arr[i];` 本意是把 num 存进数组。

**诊断**：
```c
int a = 5, b = 10;
a = b;
```
问：执行完 `a` 和 `b` 分别是几？

（答 `a=10, b=10` 正确。答 `a=5, b=5` 说明方向反了。）

**纠正**：把 `=` 读成"把右边装进左边"，不要读成"等于"。配 `references/tracing.md` 里的前后两张盒子图。

## 2. 整数除法

**错误模型**：除法就是数学除法，会得到小数。

典型症状：`int avg = sum / len;` 然后平均值算出来少了小数部分，导致后续比较统计出错。

**诊断**：
```c
printf("%d\n", 505 / 10);
```
问：输出是多少？

（答 50 正确。答 50.5 或 51 说明有这个错误模型——注意答 51 是另一个误解，以为会四舍五入。）

**纠正**：两个 int 相除，结果也是 int，小数直接砍掉不是四舍五入。要得到小数，让其中一边变成浮点：`sum * 1.0 / len`。

**连带检查**：`%d` 打印 double 会输出乱码。改完除法一定要连着检查 printf 的格式符。

---

## 3. 局部数组不会自动清零

**错误模型**：定义了 `int arr[10];` 里面就是 10 个 0。（学过 Java 的学生尤其容易这样想。）

**诊断**：
```c
int arr[5];
printf("%d\n", arr[0]);
```
问：这会输出 0 吗？

**纠正**：不会，是内存里残留的垃圾值，每次运行可能都不一样。要清零得写 `int arr[10] = {0};`。

这条会连带影响查重循环的写法——为什么要用 `i < count` 而不是 `i < len`。

---

## 4. 函数没有在所有路径上返回

**错误模型**：函数里写了 `return`，就算返回过了。

典型症状：
```c
int contains(int arr[], int len, int num) {
    for (int i = 0; i < len; i++) {
        if (arr[i] == num) return 1;
    }
    // 这里没有 return
}
```
报错：`Non-void function does not return a value in all control paths`

**诊断**：问「如果数组里一个都没匹配上，循环跑完之后，这个函数返回什么？」

**纠正**：编译器要求每一条可能的执行路径末尾都有返回值。在循环外面补 `return 0;`。

**连带检查**：学生补 `return 0;` 时，很可能放进循环里面了。追问：「放在 for 里面和放在 for 外面，结果有什么不一样？」（放里面的话，第 0 个元素比不上就立刻返回了，后面根本没检查。）

---

## 5. srand 放在循环里

**错误模型**：每次要随机数都得先播种。

典型症状：循环里反复调 `srand(time(NULL))`，结果一秒内生成的数全一样，去重循环直接死循环。

**诊断**：问「`time(NULL)` 返回的是什么？一秒之内连续调两次，返回值一样吗？」

**纠正**：`srand` 整个程序只调一次，放在所有随机数之前。种子一样，`rand()` 序列就完全一样。

---

## 6. rand() 的范围

**错误模型**：`rand() % 100` 是 1 到 100。

**诊断**：问「`rand() % 100` 最小可能是几？最大可能是几？」

（正确答案 0 和 99。）

**纠正**：取模的结果是 0 到 (n-1)。要 1~100 得 `rand() % 100 + 1`。

推广：要 a~b 之间，写 `rand() % (b - a + 1) + a`。让学生代入 a=1, b=100 验证一下。

---

## 7. scanf 忘记 &

**错误模型**：跟 printf 一样传变量名就行。

**诊断**：问「`printf("%d", x)` 和 `scanf("%d", &x)`，为什么一个要 `&` 一个不要？」

**纠正**：printf 只是读取 x 的值，传值就够。scanf 要**修改** x，必须知道 x 在哪儿，所以要传地址。

这条是通往"函数传参为什么要传地址"的入口，值得讲透。

---

## 8. 传值 vs 传地址

**错误模型**：把变量传进函数，函数里改了，外面也会跟着变。

**诊断**：
```c
void change(int x) { x = 100; }

int main() {
    int a = 5;
    change(a);
    printf("%d\n", a);
}
```
问：输出是几？

（答 5 正确。答 100 说明有这个错误模型。）

**纠正**：函数参数是**复制品**。`change` 里的 `x` 和 `main` 里的 `a` 是两个不同的盒子，改了复制品不影响原件。要改原件，得把地址传进去。

配内存图：画出 main 的 a（0x100）和 change 的 x（0x200）两个独立的格子。

## 9. 指针变量自己也占内存

**错误模型**：指针就是一个箭头，不占地方。

**诊断**：问「`int *p;` 这个 p 自己有没有地址？`&p` 是合法的吗？」

**纠正**：p 是一个变量，装的内容恰好是个地址。它自己也有地址。这是理解二级指针和"指针作参数为什么改不了指针本身"的基础。

---

## 10. 循环里的 i++ 位置

**错误模型**：`for` 的 `i++` 一定会执行，跟循环体内做了什么无关。

这条其实不是错误模型，是**没意识到可以控制**。学生知道 `i++` 会自动跑，但想不到可以把它挪出来。

**诊断**：问「如果这一轮的数不能要，想让下一轮还填同一个格子，有什么办法？」

**纠正**：两种写法都给，让学生选一种：
```c
// 写法 A：for 里不写 i++，成功才 ++
for (int i = 0; i < len;) {
    if (成功) { arr[i] = num; i++; }
}

// 写法 B：用 while + 计数器
int count = 0;
while (count < len) {
    if (成功) { arr[count] = num; count++; }
}
```

## 11. 数组下标越界

**错误模型**：写越界了程序会报错。

**诊断**：
```c
int arr[5] = {1,2,3,4,5};
printf("%d\n", arr[5]);
```
问：这会报错吗？

**纠正**：C 不检查越界，程序照跑，读到的是隔壁内存的垃圾值，写进去还可能破坏别的变量。这是 C 和 Java/Python 最危险的区别之一。数组 `arr[n]` 的合法下标是 0 到 n-1。

---

## 12. == 写成 =

**诊断**：
```c
int a = 5;
if (a = 3) {
    printf("进来了\n");
}
```
问：会打印吗？`a` 最后是几？

（会打印，`a` 变成 3。因为 `a = 3` 是赋值表达式，值为 3，非 0 即真。）

**纠正**：`=` 赋值，`==` 比较。这个错误编译器通常只给 warning 不给 error，所以特别难查。

---

## 用法建议

不要一次问一串诊断题，那会变成考试。

正确用法是：看到学生代码里有某个症状，或者他卡在某处，**只问对应的那一条**。答对就跳过，答错就沿着纠正路径走一小段，然后回到原来的题目。
