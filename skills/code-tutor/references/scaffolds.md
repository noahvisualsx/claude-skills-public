# 台阶题的出题模板

配合 SKILL.md 里的六级台阶使用。这里是每一级的具体出法和现成例子。

---

## 第 5 级：挖空题

**怎么挖**：只挖"想错了就一定错"的地方，不挖打字就能填对的地方。

好的挖空点：
- 循环的边界条件（`i <= n` 还是 `i < n`）
- 赋值的方向
- `return` 的位置
- 数组下标的表达式（`n - i` 还是 `n - i + 1`）
- 判断条件的正负（`if (flag)` 还是 `if (!flag)`）

坏的挖空点：
- `printf` 里的字符串
- 变量的类型声明（除非考点就是类型）
- `#include` 这一行

**一次最多挖 3 个空。** 挖 5 个以上就退化成"自己写"了，台阶没起作用。

### 例：图形题挖空

```c
#include <stdio.h>

int main(void) {
    int n = 6;

    for (int i = 1; i <= n; i++) {
        // 打空格
        for (int k = 1; k <= ______; k++) {    // ① 第 i 行有几个空格？
            printf(" ");
        }
        // 升序 1 到最大数
        for (int j = 1; j <= ______; j++) {    // ② 第 i 行的最大数字是多少？
            printf("%d", j);
        }
        // 降序回到 1
        for (int j = ______; j >= 1; j--) {    // ③ 从几开始降？
            printf("%d", j);
        }
        printf("\n");
    }
    return 0;
}
```

答案：① `i - 1` ② `n - i + 1` ③ `n - i`

③ 是最容易错的——学生多半会填 `n - i + 1`，导致中间数字打两遍。这个错误值得让他犯一次，然后自己跑出来看。

### 例：查重函数挖空

```c
int contains(int arr[], int len, int num) {
    for (int i = 0; i < ______; i++) {     // ① 比到哪里为止？
        if (arr[i] == num) {
            return ______;                  // ② 找到了返回几？
        }
    }
    return ______;                          // ③ 没找到返回几？
}
```

## 第 4 级：排序题

给出**全部正确**的代码行，打乱顺序，让学生排。

**不要加干扰项。** 研究显示掺入错误代码行会让完成率下降约 26%、认知负担上升，而且对学习没有额外好处。

缩进要保留还是去掉？给新手**保留缩进**，缩进本身是结构的提示，这一级的目标是理解顺序不是理解缩进。

### 例：尾插法建链表

把下面的行排成正确顺序：

```
    tail = p;
    p->next = NULL;
    tail->next = p;
    p->data = x;
    struct Node *p = malloc(sizeof(struct Node));
    if (head == NULL) { head = p; tail = p; }
    else {
```

排完追问一句：「`tail->next = p;` 和 `tail = p;` 这两行如果换顺序，会发生什么？」

这句追问比排序本身更重要——它逼学生去追踪，而不是靠感觉排。

## 第 3 级：预测输出

给完整代码，问输出。

**技巧：把循环次数改小。** 原题跑 10 轮，改成跑 3 轮。学生能在脑子里跑完 3 轮，跑不完 10 轮。

```c
int arr[3] = {5, 2, 8};
int sum = 0;
for (int i = 0; i < 3; i++) {
    sum += i;              // 注意这里是 i 不是 arr[i]
}
printf("%d\n", sum);
```

问：输出几？

（答 3。如果学生答 15，说明他没注意到累加的是下标而不是元素——这正是要暴露的。）

## 第 2 级：带着追踪

给出追踪表的前两行，让学生填第三行。表格格式见 `tracing.md`。

关键：**第三行要安排成有分支的那一轮**（撞车了、条件不成立了、要退出了），不要安排成平淡的一轮。

## 第 1 级：带标注的范例

完整正确代码，每个逻辑块上面加一行注释说明这块**在干什么**（不是怎么做）。

这叫子目标标注（subgoal labels）。研究显示带标注的范例比不带的效果更好，学生更容易看到代码的结构而不是表面细节。

标注写"目的"不写"操作"：

```c
// 好的标注：写目的
// 1. 生成不重复的随机数填满数组
// 2. 把所有元素加起来
// 3. 算出平均值
// 4. 数出比平均值小的有几个

// 坏的标注：写操作（学生看了等于没看）
// 定义一个 for 循环
// i 从 0 开始
// 调用 rand 函数
```

在这一级，可以让学生做的事是：**把标注和代码块配对**（给打乱的标注，让他标到对应的代码块上）。这比纯阅读有参与感。

## 升级的时机

学生在某一级连续做对两题，就往上升一级。

不要问"要不要升级"，直接出上一级的题。如果他做不出来，安静地退回去，不要说"看来还是太难了"。

---

## 降级的话术

降级时不要说破，换个说法引出：

| 不要说 | 改成说 |
|---|---|
| 这题对你来说太难了 | 我们把它拆开，先只看中间三行 |
| 我给你降低一下难度 | 换个角度：我先写出来，你找找哪一行有问题 |
| 看来你还没掌握 | 这里有个地方容易绕，我们慢一点过 |
| 你再想想 | （直接给下一级的题，不要空转） |

"你再想想"是最没用的一句话——学生如果能想出来，第一次就想出来了。卡住的时候重复"再想想"只会增加挫败。直接降级。
