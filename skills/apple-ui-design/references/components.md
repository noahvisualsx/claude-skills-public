# 组件规则速查

来源：HIG 各组件页（Buttons、Toolbars、Sidebars、Menus、Context menus、Popovers、Panels、Sheets、Alerts、Segmented controls、Toggles、Pop-up / Pull-down buttons、Search fields、Lists and tables、Scroll views、Offering help、Icons、SF Symbols）。提炼整理，非原文。

---

## 按钮 Buttons

- 按钮 = **样式**（大小、颜色、形状）+ **内容**（符号 / 文字）+ **角色**（normal / primary / cancel / destructive）。
- 点击区至少 **44×44 pt**（visionOS 60×60）；周围留足空白。
- 自定义按钮**必须有按下状态**（macOS 还要有悬停状态）。
- 一个视图里醒目样式（`.borderedProminent` / `.glassProminent`）的按钮 **1–2 个**，给最可能的那个操作。
- 用**样式**而不是**尺寸**区分首选项：同一组选择的按钮一样大。
- 内容层很花哨时，按钮标签保持单色。
- 图标按钮用熟悉的符号（分享 = `square.and.arrow.up`）；文字更清楚时用文字，动词开头。
- macOS / visionOS 上悬停会出 tooltip（SwiftUI `.help("…")`）：简短说明做什么，别重复按钮名，用句子式大小写。
- **primary 角色**给最可能选的按钮，它响应回车；临时视图（Sheet、弹窗）里按回车会自动确认关闭。
- **破坏性操作永远不给 primary 角色**，即使它最常用（人会不看就按）。
- **macOS 专有**：
  - 标准按钮叫 push button；打开新窗口 / 视图 / app、或需要进一步输入的按钮，标题末尾加「…」。
  - 两行文字或高图标才用 flexible-height push button。
  - square（gradient）button 只放在视图内部（比如表格下方的 +/−），只放符号，不放文字，不放进工具栏。
  - help 按钮（圆形问号）每个窗口最多一个，打开与当前上下文相关的帮助。
  - 支持 spring loading（拖着东西压按钮触发）更好。

## 开关 / 复选框 / 单选 Toggles

- 开关（switch）只放在**列表行 / 表单行**里；列表之外用"表现得像开关的按钮"。
- macOS：窗口主体里用 switch / checkbox / radio，**不放在窗口边框（工具栏）**；需要强调的设置用 switch，分组表单单行可用 mini switch；**一般不要用 switch 替换 checkbox**；有层级关系的设置用 checkbox；两个以上互斥选项用 radio（别太多）；单个开关型设置优先 checkbox。
- 开关状态的视觉差异要明显；不要随便改开关的默认颜色。

## 分段控件 Segmented controls

- 用于**紧密相关**、影响同一对象 / 视图的几个选择；数量要少；每段宽度尽量一致。
- 一个分段控件里只用文字**或**只用图片，不混；标签用名词。
- 主窗口区域切换视图用 tab view，不用分段控件；做内容筛选时考虑 split view。

## 弹出按钮 / 下拉按钮

- **Pop-up button**：一组互斥选项（像选择器），要有合理默认值，按钮上显示当前值让人能预判。
- **Pull-down button**：和按钮本身相关的一组**命令**；别把整个视图的操作全塞进一个；破坏性项要标出并确认；可以做一个「更多」（`ellipsis`）下拉放次要操作。

## 工具栏 Toolbars

- 只放主要任务需要的项，别拥挤；窗口变窄时系统自动生成溢出菜单，**别自己加溢出菜单**，也别让默认宽度就溢出。
- 需要时加一个「更多」菜单放次要操作。
- iPadOS / macOS 长时间使用的 app 支持自定义工具栏。
- **减少工具栏自定义背景和染色控件**：让内容层决定工具栏的颜色，必要时用滚动边缘效果区分。
- 用系统组件，圆角会自动与栏同心；自定义组件的圆角也要同心。
- **标题**：每个窗口一个有用的标题，<15 字符；**不要用 app 名当标题**；多余时可以留空。
- 返回 / 关闭用系统标准按钮和符号，**不要写"返回""关闭"文字**。
- 优先用无边框的系统符号（不要 `plus.circle` 这类带圈的），hover 和选中态系统会画。
- 主操作（完成 / 提交）用 prominent 样式，**只有一个**，放在**尾部**。
- 三个区域：**前部**（返回、侧栏开关、标题、文档菜单，不可自定义）· **中部**（常用控件，可自定义，窄时折叠）· **尾部**（必须一直可见的项、检查器按钮、搜索、更多、主操作）。
- 按功能和使用频率分组，**最多约 3 组**；导航和关键操作（完成 / 关闭 / 保存）单独成组；文字按钮之间用固定间隔隔开，文字按钮和图标按钮不要挨着。
- 可以情境性地隐藏工具栏做沉浸，但要能可靠地找回来。

## 侧边栏 Sidebars

- 位于前侧，用于顶层导航 / 集合（文件夹、播放列表）；占空间大，空间小时考虑标签栏（iPad 可用 `sidebarAdaptable` 两者兼得）。
- 侧边栏浮在 Liquid Glass 层；内容可以横向滚到它下面，或用 `backgroundExtensionEffect()` 延伸背景。
- 允许用户自定义侧栏内容和顺序；层级最多两级，更深用 split view 加中间列表；两级时分组标题要短。
- 用 SF Symbols 做侧栏图标；自定义图标做成 custom symbol 而不是位图。
- 允许隐藏侧栏（macOS：显示 / 隐藏按钮 + 「显示方式」菜单里的命令），但**默认不要隐藏**。
- **图标颜色**（2026 更新）：默认跟随 app 强调色 / 用户选的系统强调色；只有少量需要表达特定含义的图标才固定颜色。
- macOS：行高、字号、图标大小跟随系统「侧边栏图标大小」设置（小 / 中 / 大）；窗口缩小时可以自动收起侧栏；**关键信息和操作别放侧栏底部**。

## 菜单 Menus（通用）

- 标签简洁清楚，标题式大小写（英文）；去掉冠词。
- 不可用的项在**主菜单**里置灰；需要更多输入才能完成的项末尾加「…」。
- **菜单图标（2026 更新）**：少而有目的 —— 只给最常用操作、关键功能、文件系统位置、已连接设备、旋转 / 翻转这类视觉概念、用户创建的内容（文件夹、文档）加图标；找不到贴切图标就不加；**同一组里要么全有图标，要么全没有**；标准操作（剪切、拷贝、粘贴…）用标准图标，AppKit / UIKit 用标准 selector 系统会自动配图标。
- 重要 / 常用项放前面；相关项分组（即使重要性不同也放一组）；注意长度。
- 子菜单少用、浅、短；子菜单里的项全不可用时，子菜单本身仍保持可用；用子菜单而不是缩进。
- 状态类菜单项：用描述当前状态的可变标签，或加动词，或两个项都列出来；「正在生效」用对勾；提供一键清除多个属性的项。

## 右键菜单 Context menus

- 只放**与点中对象最相关**的少量操作；全 app 一致地支持右键菜单。
- **右键菜单里的每个操作在主界面里也要能找到**（右键菜单是捷径，不是唯一入口）。
- 子菜单最多一层；**不可用的项直接隐藏，不要置灰**（和主菜单相反）。
- 快捷键显示在主菜单里，不显示在右键菜单里。
- 一个对象要么给右键菜单，要么给编辑菜单，不要两个都给。
- 顶部操作要和滑动操作保持一致（2025 起）；可以用右键菜单替代面板 / 检查器来放高频功能；高度别超过窗口。

## 弹出框 Popovers

- 放**少量**信息或功能，交互后就消失；需要临时内容时用它代替占地方的侧栏 / 面板。
- 箭头尽量直指触发它的元素，不要盖住触发元素和必要内容。
- 只有需要「确认 / 取消修改」时才放关闭 / 取消 / 完成按钮；点外面自动关闭时**要保存用户已做的修改**，只有点了明确的取消才丢弃。
- **一次只显示一个**，绝不嵌套弹出框；上面除了 Alert 什么都不要盖。
- 大小刚好容纳内容；尺寸变化要有动画。
- **不要用弹出框显示警告**（容易错过 / 误关）—— 用 Alert。
- macOS：可以允许把弹出框拖出来变成独立面板（detach）。
- 删掉你给 popover 内容加的自定义背景 / 视觉效果视图，让系统画玻璃。

## 面板 Panels（macOS）

- 浮在其它窗口上，提供与当前窗口 / 选中内容相关的辅助控件或信息；检查器（inspector，内容随选中变化）适合用面板；内容固定的 Info 窗口用普通窗口。
- 优先用滑块、步进器这类**直接调节**的控件，少用需要打字的控件。
- 需要标题栏（名词短标题，如「字体」「颜色」），在菜单里叫「显示字体」而不是「显示字体面板」。
- app 激活时把所有面板带到前面，app 不活跃时隐藏面板；不进 Window 菜单的文档列表；一般不给最小化按钮。
- **HUD 风格面板**（深色半透明）：只在媒体类 app、普通面板会挡住关键内容、或几乎不需要控件时用；**保持小**、少用颜色、切换模式时保持同一种面板风格。

## Sheets

- 短暂、偶尔的模态任务；复杂 / 长流程考虑别的形式；一次只显示一个。
- 需要反复输入并观察结果时用面板，不用 Sheet。
- 提供「完成」之外的退出方式（取消、下滑、Esc）；可调大小的 Sheet 有抓手（iPhone 支持 medium detent 做渐进披露）。
- macOS：Sheet 用默认大小、保留上下文；允许用户在 Sheet 打开时操作 app 的其它窗口；按钮放置位置按平台惯例（2026 年 3 月更新了按钮摆放指引）。
- Sheet 圆角更大，iPhone 半高 Sheet 离开屏幕边缘；检查靠近圆角的内容。

## 警告框 Alerts

- **少用**；不要只为「告知」而弹；常见且可撤销的操作（即使是删除）不要弹；**启动时别弹**。
- 标题直接说明情况；补充说明有价值才写；不要解释按钮。
- 按钮标题简短、合逻辑、最好是动词；**非纯告知类不要用「好 / OK」当默认按钮**。
- 破坏性操作：按钮用 destructive 样式，并且**一定有取消**；提供 Esc 等取消方式。
- 与用户主动操作相关的一组选择用 action sheet / confirmationDialog，不用 alert；弹窗内容别长到需要滚动。

## 搜索 Search fields

- 占位符说明能搜什么；输入即开始搜；给建议词；结果简洁；可筛选（scope bar、tokens）；默认范围宽一点，让人收窄。
- macOS：大多数情况下放在**工具栏尾部**；侧边栏里筛选导航时放侧栏顶部；专门的「发现」区域可以作为侧栏 / 标签栏的一项，进入时自动聚焦。
- iOS：有空间放底部；需要把底部让给内容时放顶部；搜索作为标签栏的一个 tab 时用系统的语义搜索 tab（自动放在最后并独立出来）。

## 列表与表格

- 文字内容优先用列表 / 表格；行文字简短；选中要有反馈。
- 多列表格：列标题清楚、点列标题排序、允许调列宽、考虑斑马纹；层级数据用 outline view。
- 2026 起列表、表单行高和内边距更大，分组圆角更大；分区标题用标题式大小写（不再强制全大写）。
- macOS 表单用 `Form` + `.formStyle(.grouped)` 自动获得新布局度量。

## 滚动视图

- 支持系统滚动手势和键盘（空格翻页、方向键、Page Up/Down）；自定义滚动也要有弹性。
- 让「可以滚」这件事显而易见（边缘露出半个项目）。
- 不要把**同方向**的滚动视图嵌套。
- 需要时按页滚动（带一点重叠保持上下文）；必要时自动滚动到选中 / 光标处，只滚必要的距离。
- 滚动边缘效果：见 `liquid-glass.md` §3.4。

## 帮助与提示 Offering help

- 提示（TipKit）用于**简单功能**：短、可执行、有吸引力；设定出现规则，别打扰已经会用的人；有代表性符号就放上（用填充变体）。
- 别解释标准组件怎么用。
- tooltip：只描述被悬停的控件，说明它做什么，别重复控件名，简短，句子式大小写，可以随上下文变化。

## SF Symbols 用法要点

- 与文字同字重、同字号，自动对齐；用 `.imageScale` 调相对大小。
- 渲染模式：单色（默认）、层级（hierarchical）、调色板（palette）、多色（multicolor）—— 按信息需要选，别为了花哨用多色。
- 变体：`.fill` 用于选中 / 强调状态和标签栏；工具栏和导航里默认用描边版；带圈 / 方框的变体不要放进已经有容器的地方（工具栏）。
- 动画：`.symbolEffect(.bounce / .pulse / .variableColor / .replace / .wiggle / .breathe / .rotate …)`，用于反馈和状态变化，别常驻抖动。
- 自定义符号从 SF Symbols app 导出模板做，保证能随字重缩放。
- 每个纯图标控件都要 `accessibilityLabel`。
