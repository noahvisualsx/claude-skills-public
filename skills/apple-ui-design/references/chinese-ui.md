# 简体中文界面：文案、标点、排版

HIG 本身不讲中文。这一页的规则来自两个可复查的来源：

1. **Apple 自己的简体中文本地化**：从 macOS 27 的 AppKit、日历、邮件、备忘录、提醒事项、预览、照片、访达、系统设置等 491 个 `.loctable` 里抽出 12,046 条「英文 → zh_CN」对照，统计写法（2026-09-23）。
2. **本机实测排版**：用 CoreText / SwiftUI 量文字宽度、查字体回落。

复查方法见文末。

---

## 1. 标点

| 规则 | Apple 本地化里的实际情况 |
|---|---|
| 引号用 **“” 弯引号**，不用「」 | “” 875 处，「」**0** 处，直引号 " 0 处 |
| 省略号用单个字符 **…**（U+2026） | … 562 处，"..." 3 处 |
| 中文句子里用**全角** ，：？！ | 全角逗号 641 处，中文后跟半角逗号 2 处；全角冒号 278，半角 0 |
| 括号全角半角都有 | （ 155 处，中文旁半角 ( 163 处 —— 同一个 app 内统一即可 |
| 完整句子（说明、错误信息）结尾用 **。**；按钮、菜单、标题不加句号 | 以 。结尾的 1754 条 |
| app 名、文件名、用户输入的名字用引号括起来 | 请退出并重启“照片”；删除“%@”？ |

## 2. 中文和英文 / 数字之间：**不要手动加空格**

- Apple 简体中文界面字符串几乎从不手动加空格：中文紧挨西文 1292 处，中间有空格 6 处；中文紧挨数字 108 处，有空格 0 处；中文紧挨 `%@` 占位符 340 处，有空格 1 处。例：「请确保URL正确，然后重试。」「在%@上找不到日历。」
- 原因：**macOS 的文字排版会自动在中文和西文 / 数字之间加间距**。实测 13pt 系统字体：
  - 「在iPhone上」宽 70.4pt，比三段单独量的和（67.2pt）多 3.25pt，每侧约 1.6pt（≈1/8 字宽）；
  - 手动写成「在 iPhone 上」宽 74.3pt，每侧 3.6pt —— 手动空格会覆盖自动间距，间隙变成两倍多，看起来松散；
  - SwiftUI `Text` 结果相同（71 / 68 / 75pt，取整后）。
- 所以界面字符串写成 `"共\(count)项"`、`"打开Skills文件夹"`，渲染出来自然有细间距。
- 网址、命令、文件路径两边**保留空格**（「先到 https://brew.sh 安装」），否则双击选不中、容易连着中文一起复制。
- 例外：网页、Markdown 正文、要导出成纯文本给别的软件看的内容，可以按「盘古之白」加空格；界面字符串不加。

## 4. 句式

- **人称用「你」**，不用「您」（Apple 本地化「你」578 处，「您」0 处）。也尽量少用「我的」「你的」。
- **确认破坏性操作**：「确定要删除这些日程吗？」/「删除“%@”？」；按钮写动作「删除」，另配「取消」。
- **出错**：「无法连接账户“%@”。」+ 下一句说怎么办「请检查网络连接，然后重试。」—— 先说结果，再说原因 / 办法，不责怪用户。
- **空状态**：短标题「无结果」「没有对话」+ 一句下一步。
- **进行中**：「正在下载…」「正在翻译3段…」—— 说清在做什么，比「处理中…」好（HIG › Generative AI 同样要求具体）。
- **按钮 / 菜单项**：动词开头、短（2–6 个字），不加句号；会打开新窗口 / 需要进一步输入的加「…」：「导出…」「共享…」「显示字体…」。
- 设置项标签是名词短语（「强调色」「侧边栏图标大小」），说明文字是完整句子。

## 5. 排版

- **字体**：不要自己指定中文字体名；系统字体 `.default` 的中文回落是苹方（PingFang SC），`.serif` 回落到宋体（Songti SC），`.rounded` / `.monospaced` 的中文回落都是苹方（本机 `CTFontCreateForString` 实测）。
- **宋体只做大标题**（≥ 17pt）：笔画细，小字号难读；正文、说明、按钮用苹方。
- **不要给中文加字距**（`.tracking` / `.kerning`）：中文本来就等宽排列，加字距会松散；西文的动态字距系统会自动处理。
- **不要用斜体强调中文**：中文字体没有真斜体，系统会机械倾斜，很难看；强调用字重或颜色。
- **行距**：多行中文正文比英文需要更松的行距，`.lineSpacing(3...5)`（13–15pt 正文）读起来更舒服；标题行不加。
- **最小字号**照 HIG：macOS 10pt（中文笔画多，说明文字建议 ≥ 11pt）。
- 数字、时间、金额用 `.monospacedDigit()` 对齐。
- 中英混排的按钮宽度差异大，按钮组别写死宽度，让它按内容撑开。

## 复查方法

```bash
# 1. 抽取系统 app 的中英对照（loctable 是 plist，顶层按语言分组）
find /System/Library/Frameworks/AppKit.framework/Resources /System/Applications/Calendar.app \
     -name "*.loctable" > files.txt
python3 - <<'EOF'
import plistlib
for f in open("files.txt").read().split():
    d = plistlib.load(open(f, "rb")); en, zh = d.get("en", {}), d.get("zh_CN", {})
    for k, v in zh.items():
        if isinstance(v, str) and isinstance(en.get(k), str): print(en[k], "→", v)
EOF

# 2. 量中西文自动间距：比较 "在iPhone上" 与三段分别量的宽度之和（见 NSString.size(withAttributes:)）
```

## 宋体 / 衬线大标题里全角标点后面多一块空（macOS 26+ 实测）

- 现象：`Text("打开一条资料，继续探索").font(.custom("Songti SC", …))` 在 App 里，逗号后面比正常多出约半个字的空；同一句用 `ImageRenderer` 渲染却正常。
- 原因：写死的字符串走 `LocalizedStringKey`，文字会被标上简体中文语言，排版时宋体、系统衬线体（New York 回落到宋体）的全角标点会被额外加宽。`Text(someString)`（变量）和 `Text(verbatim:)` 不带语言标记，间距正常。
- 另外，系统衬线体（`.system(design: .serif)`）本身没有中文，逗号前后也会多空；中文大标题直接用宋体（`STSongti-SC-Regular` / `-Bold`）。
- 做法：带标点的中文衬线标题写成 `Text(verbatim: "…")`；正文用苹方的不受影响。
- 验证：在 App 截图上量“最宽空白 / 整行宽”，和 CoreText 算出的理论值比，别只看 `ImageRenderer`。
