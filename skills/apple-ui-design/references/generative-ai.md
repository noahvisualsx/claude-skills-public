# 生成式 AI 功能的界面

来源：HIG「Generative AI」（2025-06 新页，2026-06-08 更新：细化结果、生成中给反馈、选择模型类型）。提炼整理，非原文。
适用于：聊天助手、翻译、摘要、自动整理、出题 / 出卡、生成图片等任何用模型产出内容的功能。

## 1. 先想清楚要不要用 AI

- 只在能带来明确价值的地方用（省时间、改善沟通、做以前做不到的事），不要为了「有 AI」而加。
- **AI 不可用时体验照样成立**：没配 API Key、断网、模型出错、用户不想用 —— 核心功能要有非 AI 的路径（手动输入、模板、上次的结果）。
- 模型会变，功能设计别绑死在某一个模型上；把「选哪个模型」和「功能本身」分开。

## 2. 透明

- **标明哪里用了 AI**：生成的内容带一个小标识（「由 DeepSeek 生成」「AI 整理」），永远不要让人以为是人写的、或是事实记录。
- **说清能做什么、不能做什么**：第一次出现时一句话介绍能力和限制；示例输入比长说明有用。
- 生成的内容可能**编造**（幻觉）：涉及事实、数字、日期、引用时提醒核对，能给来源就给来源链接。

## 3. 隐私

- **选合适的模型位置**：本机模型（Foundation Models 的 `SystemLanguageModel`）数据不出设备、离线可用；服务器模型能力更强但数据要上传 —— 说清楚走的是哪条路。
- **发送个人信息前先征得同意**：日记、笔记、聊天记录、个人档案、照片、使用数据属于敏感内容；第一次要把这些发给云端模型前明确询问，并且只发完成任务所需的最少数据。
- **说明数据怎么用、存在哪、存多久**；给关闭入口（设置里能关掉「让助手读取日记」）。

## 4. 输入

- 用示例引导：给 3–5 个不同方向的示例输入（可点击填入），暗示能做什么。
- **不可逆或影响大的操作先确认**：AI 要删除、发送、下载、修改文件、付费、对外发布前，先把它打算做的事列出来让人点确认；能撤销的操作也要给撤销。
- 不要自动替人做重要决定。

## 5. 输出

- **在结果旁边放「编辑 / 撤销 / 重试 / 调整」**，并在修改生效时给反馈（「已按你的修改重新生成」）。
- 被拦截或结果不好时，**教人怎么改请求**，而不是只说「失败」：说明原因 + 建议换个说法 / 缩小范围。
- **考虑处理时间**：快的（< 1 秒）直接出；慢的边生成边显示（流式），并允许取消；很慢的放后台、完成后通知。
- **生成中的文案要具体**：「正在翻译3段…」「正在从12篇笔记里整理要点…」，不说「处理中…」。
- 合适时**给几个明显不同的版本**让人挑（回复思路、标题候选），而不是只给一个。
- 让人能**反馈结果好坏**（👍 / 👎 或「不准确」），并在界面里说明反馈的用途。
- 注意版权：不要生成与已发表作品高度相似的内容；图片 / 长文生成要有防护。

## 6. 审查清单（加到 audit-checklist 的 F 节一起过）

- [ ] 生成的内容有 AI 标识？（P1）
- [ ] 没有 API Key / 断网时，功能有清楚的提示和非 AI 的替代？（P1）
- [ ] 第一次把日记、笔记、个人档案等发给云端模型前征得同意，并能在设置里关掉？（P0）
- [ ] AI 触发的删除、发送、下载、写文件、改日历等操作先确认、可撤销？（P0）
- [ ] 结果旁有重试 / 编辑 / 复制；失败时告诉人怎么改？（P1）
- [ ] 生成中有具体进度文案、可取消？（P2）
- [ ] 数字、日期、事实类输出提醒核对或给来源？（P2）
