# macOS 专项

来源：HIG「Designing for macOS」「The menu bar」「Windows」「Panels」「Keyboards」「Settings」「Going full screen」「Dock menus」「Layout」「Dark Mode」。提炼整理。

## Mac 的使用特征（设计前先想清楚）

- 大屏、高分辨率，常接多块显示器（包括 iPad 当副屏）；观看距离约 30–90 cm。
- 键盘 + 高精度指针（触控板 / 鼠标）+ 游戏手柄 + Siri 混用；**精确选择、快捷键、全键盘操作**是 Mac 用户的核心期待。
- 一次可能只用几分钟，也可能专注几个小时；同时开很多 app，频繁切换 —— 活跃 / 非活跃窗口之间要切得顺。

## Mac 上的最佳做法

- **利用大屏**：更少的层级嵌套、更少的模态，同时保持舒适的信息密度。
- 窗口可以自由调整大小、隐藏、移动；支持全屏（沉浸、无干扰）。
- **所有命令都能在菜单栏里找到**。
- 支持像素级精确的选择和编辑。
- **处理键盘快捷键**，支持纯键盘工作流。
- 支持个性化：自定义工具栏、窗口里显示哪些视图、颜色和字体。

## 菜单栏

- 支持系统默认的菜单和顺序：App 菜单、文件、编辑、格式、显示、（app 专属菜单）、窗口、帮助。
- **菜单项始终显示同一套**，不可用时置灰而不是隐藏（这样用户才能学到 app 能做什么）；右键菜单相反，不可用的直接隐藏。
- 菜单标题尽量一个词。
- 标准菜单项要支持它们的标准快捷键（⌘C / ⌘V / ⌘Z / ⌘, / ⌘W / ⌘Q …）。
- **App 菜单**：「关于 X」放第一个并单独一组；「设置…」（⌘,）只放 app 级设置；自定义的 app 级配置项放在设置之后；「隐藏 X」「隐藏其他」「全部显示」「退出 X」。About / Hide / Quit 里的 app 名用 16 字符以内的短名。
- **显示（View）菜单**：即使只支持一部分功能也要有；显示 / 隐藏项的标题要反映当前状态（工具栏隐藏时显示「显示工具栏」）；带标签页的 app 可以把每个标签页做成 View 菜单里的项并配快捷键。
- 「编辑」里的删除叫 Delete（删除），不叫 Erase / Clear；撤销 / 重做写清楚撤销的是什么（「撤销输入」）。
- 自动保存优先于让人反复按保存；复制文档用 Duplicate（副本）而不是另存为。

### 菜单栏附加项（Menu bar extra，状态栏图标）

- 用**符号**做图标（黑 + 透明定义形状，系统会按外观上色）。
- 点击时**显示菜单而不是弹出框**，除非功能复杂到菜单放不下。
- **让用户决定**要不要把图标放进菜单栏（在设置里给开关，引导时可以提示）。
- 不要依赖它一定存在 —— 系统会因为空间不够把它藏起来，也猜不到它的位置。
- 同样的功能在别处也要能用（Dock 菜单、主窗口、快捷键）。

## 窗口

- **不要做自定义窗口框架和控件**，不要仿造系统窗口外观；用户靠系统外观区分前台窗口（key / main / inactive 状态的差异要保留）。
- 内容要能随窗口尺寸流畅适配；在合适的时候开新窗口（帮助多任务 / 保留上下文），也提供「在新窗口中打开」。
- 面向用户的文案一律叫「窗口」，不要说 scene 之类的实现术语。
- **底栏只放少量和窗口内容直接相关的信息**，关键信息和操作不要放底部。
- 2026 起窗口圆角更大；用标准分栏（`NavigationSplitView` / `NSSplitViewController`）获得流畅的列宽调整。

## 面板 / 浮动窗口 / 刘海类、菜单栏类 app

- 浮动面板（`NSPanel`）是给「与当前工作相关的辅助控件」的：见 `components.md` 的 Panels 一节。
- **刘海 / 顶部浮层类 app**（HIG 没有专门条目，以下由 Panels、Popovers、Layout、Materials、Accessibility 推导）：
  - 它本质是一个**功能层浮层**，最接近 popover / HUD：适合用 `.regular` Liquid Glass（或老系统的 `.hudWindow` / `.popover` 材质）；里面的卡片、列表属于内容层，不要再上玻璃。
  - 保持小而专注：一次一个任务，渐进式披露；别把设置塞进浮层，设置放进标准的「设置」窗口（⌘,）。
  - **自动收起要可预期、可打断**：鼠标停在上面时不收起；需要阅读的内容（翻译结果）不能只靠定时浮层展示，要能在面板或历史里找回（HIG：少用限时界面）。
  - 不要遮挡顶部摄像头区域里的关键内容；内容要避开刘海本身。
  - 键盘：浮层出现时 Esc 关闭、方向键 / ⌘数字 选择、回车执行；焦点离开时把焦点还给原来的 app。
  - 跟随系统深浅外观；如果提供「主题」，默认应跟随系统，并保证每个主题在「提高对比度」「降低透明度」下仍然可读。
  - 所有功能在别处也能触发（菜单栏附加项的菜单、快捷键、设置窗口），因为浮层可能被别的全屏 app 挡住。
- HUD 面板只用于媒体类、或普通面板会挡住关键内容的场景，保持小、少用颜色。

## 键盘

- 尽量支持全键盘访问（Full Keyboard Access）：Tab / Shift-Tab 在控件间移动、Control-Tab 在控件组之间移动、空格激活、Esc 取消。
- **尊重标准快捷键，不要挪作他用**；自定义快捷键避开系统保留的组合（⌘空格 Spotlight、⌘Tab、⌃F1–F7 键盘访问、⌘F5 VoiceOver、⌘` 切窗口 等）。
- 修饰键顺序显示为 ⌃ ⌥ ⇧ ⌘；自定义快捷键优先 ⌘ + 字母，需要更多再加 ⇧ / ⌥；只用 ⌃ 的组合留给系统。
- 快捷键显示在主菜单里（右键菜单不显示）。
- 全局快捷键（app 不在前台也生效）要能在设置里修改 / 关闭，并检测冲突。

## 设置窗口

- ⌘, 打开；只放 app 级设置；用标准 `Settings` 场景 + `Form(.grouped)`，按类别分页（工具栏样式的页签）。
- 设置改了立即生效，不需要「应用 / 保存」按钮。
- 标签简洁，说清控制什么；复杂项配一行说明文字。

## 全屏

- 支持全屏的窗口在全屏时隐藏工具栏 / 菜单栏也要能用所有功能；提供可靠的方式找回隐藏的控件。

## Dock 菜单

- 放少量高频、在 app 不在前台时也有用的命令（新建窗口、开始 / 停止某个任务）；菜单栏附加项的功能在这里也放一份。

## 深色模式 / 强调色（macOS 特有）

- 用户选「石墨」强调色时窗口会跟随桌面图片着色：自定义组件的**中性状态**背景带一点透明来跟随着色，有颜色的状态不要透明。
- app 强调色只在用户选了「多色」时生效；选中高亮、侧栏图标、按钮都用 `controlAccentColor`，不要写死。
- 非 key 窗口里选中项用 `unemphasizedSelectedContentBackgroundColor`。
