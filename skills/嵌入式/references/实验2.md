# 一、设计思路
GPIO 推挽输出原理：推挽输出结构内部由一个 P-MOS 管和一个 N-MOS 管互补组成。当输出寄存器写 1 时，P-MOS 导通、N-MOS 截止，引脚输出高电平；写 0 时，N-MOS 导通、P-MOS 截止，引脚输出低电平。推挽输出可以主动输出高、低两种电平，驱动能力强，适合直接驱动 LED 等负载。
电路设计：与实验一相同，电源 POWER（3.3V）经 33Ω 限流电阻 R1 接 LED 正极，LED 负极接 PA1 引脚。PA1 输出低电平时 LED 导通点亮，输出高电平时 LED 两端无压差而熄灭。程序设计：将 PA1 配置为推挽输出，在主循环中每隔 500ms 翻转一次 PA1 的电平，从而实现 LED 每 500ms 闪烁一次。
# 二、STM32CubeMX 工程配置
（1）打开 STM32CubeMX，点击 ACCESS TO MCU SELECTOR，搜索并选择芯片 STM32F103C6Tx，点击 Start Project。
（2）在 Pinout & Configuration 界面点击 PA1 引脚，设置为 GPIO_Output，GPIO 模式为默认的 Output Push Pull（推挽输出）。
（3）在 Project Manager 界面中，其余配置与实验一保持一致，只需将 Project Name 修改为“{后4位}-test2”（学号后 4 位-test2，表示第 2 次实验）；Toolchain/IDE 选择 MDK-ARM，固件包选择 STM32Cube_FW_F1_V1.8.0。
（4）在 Code Generator 界面勾选“Generate peripheral initialization as a pair of '.c/.h' files per peripheral”，点击 GENERATE CODE 生成代码，然后点击 Open Project 用 Keil 打开项目。
# 三、Keil 程序编写与编译
（1）在 Keil 的 Project 窗口中，点击 Application/User/Core 目录左边的“+”展开目录，双击 main.c 文件将其打开。
（2）找到第 95 行的 while(1) 循环，在循环里面添加如下 2 行代码：
```
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_1);
HAL_Delay(500);
```
其中，HAL_GPIO_TogglePin 是翻转引脚电平的函数，第 1 个参数是端口基地址，PA1 属于 A 端口，所以为 GPIOA；第 2 个参数是引脚编号，PA1 对应 GPIO_PIN_1。HAL_Delay 是延时函数，参数 500 表示延时 500ms。两行代码配合实现 LED 每 500ms 闪烁一次。
（3）点击 Build 编译项目，输出窗口显示“0 Error(s)”，编译成功，并在 MDK-ARM/{后4位}-test2 目录下生成 {后4位}-test2.hex 文件（若未生成，在 Options for Target → Output 中勾选 Create HEX File 后重新编译）。
# 四、Proteus 仿真验证
（1）打开 Proteus，新建项目，步骤与实验一相同，项目名称修改为 {后4位}-test2。
（2）添加元器件 STM32F103C6、RES、LED-RED，并通过 Terminals Mode 添加电源 POWER；按照 POWER → R1 → LED 正极、LED 负极 → PA1 的方式连接电路，将电阻阻值修改为 33。
（3）点击 Design → Configure Power Rails…，在 GND 中添加 VSSA，在 VCC/VDD 中添加 VDDA 并将电压改为 3.3V（这一步不能遗漏，否则芯片无法正常仿真）。
（4）双击 STM32 芯片，在 Program File 中导入 {后4位}-test2.hex 文件，点击 OK。
（5）点击运行按钮开始仿真，观察到 LED 以 500ms 的间隔不断闪烁，PA1 引脚状态在红色（高电平）和蓝色（低电平）之间交替变化，验证了程序与电路设计正确。
