# 嵌入式实验报告：只填「实验方法和步骤」

**范围只有第 4 栏**「实验方法和步骤（含设计）」。第 5 栏（程序及测试结果截图）、第 6 栏（实验分析与体会）、表头一律不动，除非用户另外要求。
本机没有 Keil / Proteus（仅 Windows），不要尝试运行或伪造截图。

## 1. 找文件、认人
- 工作目录一般是 `~/Desktop/嵌入式/`：`实验N.pdf`（操作书）+ `学号_姓名_实验报告_0N.docx`（报告模板）。
- 从报告表头读 **学号**（如 2400000123），项目名用学号后 4 位：`0123-testN`。
- 报告号 0N 对应实验 N；报告的「实验名称 / 实验内容」可再核对一遍。

## 2. 准备步骤文本
- `references/实验1.md`～`实验3.md` 是已整理好的步骤（开发环境搭建 / 点亮一盏灯 / 按键控制灯），项目名处写成 `{后4位}` 占位。实验 1～3 直接用。
- 新实验（实验4 以后）或操作书有改动时，照同样格式新写一份，并存进 `references/实验N.md` 供下次复用：
  - 读操作书文字：`pdftotext 实验N.pdf -`
  - 很多关键设置只在截图里（Project Manager 配置、电路连线、引脚 User Label、代码截图），用 `pdftoppm -jpeg -r 80 -f 页 -l 页 实验N.pdf 前缀` 渲染相关页再看图。
  - 结构固定四块：`# 一、设计思路`（原理 + 电路接法 + 程序思路）→ `# 二、STM32CubeMX 工程配置` → `# 三、Keil 程序编写与编译` → `# 四、Proteus 仿真验证`；每步用 `（1）（2）…` 开头；代码用 ``` 包起来。
  - 固定事实：芯片 STM32F103C6Tx；固件包 STM32Cube_FW_F1_V1.8.0；Toolchain MDK-ARM；Code Generator 勾选 .c/.h 分文件；LED 电路是 POWER(3.3V) → 33Ω 电阻 R1 → LED 正极，LED 负极 → PA1（低电平点亮）；Proteus 必须 Design → Configure Power Rails：GND 加 VSSA，VCC/VDD 加 VDDA 且电压改 3.3V；双击芯片 Program File 加载 hex。

## 3. 写进报告
```bash
S=~/.claude/skills/嵌入式/scripts
python3 $S/fill_steps.py "学号_姓名_实验报告_0N.docx" ~/.claude/skills/嵌入式/references/实验N.md --sid 学号
```
- 默认原地写入，同目录留 `.docx.bak` 备份；该栏已有内容会拒绝，确认要覆盖再加 `--force`。
- 脚本只替换「（主要描述实验步骤）」提示行之后、该单元格结束前的内容，提示行本身保留。
- 格式：小标题加粗、正文小四首行缩进 2 字、1.5 倍行距、代码 Consolas 五号左缩进。

## 4. 核对
- `textutil -convert txt -stdout 报告.docx | sed -n '/实验方法/,/程序及测试/p'`，确认文字、顺序、项目名 `0423-testN` 正确，没有残留 `{后4位}`。
- LibreOffice 转 PDF 在本机缺中文字体（连模板原文都显示不出），不能用来判断排版；提醒用户用 Word 打开看一眼即可。
- 确认无误后删除 `.bak`，或告诉用户备份位置。
