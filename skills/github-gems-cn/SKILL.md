# GitHub 开源推荐帖

用户的账号会定期发这种帖子：发现一个刚火起来的开源项目，用两三行说清它替代了什么、有多小或多免费、能干什么，配一段录屏，链接放首评。样板是 Compositor 那条（见文末）。

用户说「找几个」，默认交付 **5 到 8 条写好的短推**，不是一份链接清单。

## 流程

### 1 找候选

```bash
python3 ~/.claude/skills/github-gems-cn/scripts/find.py              # 最近 60 天，500 星以上
python3 ~/.claude/skills/github-gems-cn/scripts/find.py --days 30 --min 1000 --query "video editor"
```

按「星/天」排序，已推荐清单里的仓库和明显不适合的方向会被自动去掉。用户点名方向（视频、设计、Mac、AI 绘图）时用 `--query` 加关键词多搜几次。

### 2 筛选

**优先**（越靠前越好）：
1. 知名付费软件的免费平替：PS、AE、Premiere、CapCut、Canva、Figma、Office、Lightroom、Notion
2. 创作者用得上的：生图、剪辑、配音、字体、素材、格式转换、录屏
3. Mac 上好用的小工具，安装包越小越好
4. Claude Code、Codex 的 skill 和插件，能马上装上玩的
5. 同一个团队一口气开源一整套的，合成一条发

**不发**：
- 版权风险：游戏移植和破解、模拟器、无水印下载全网视频、第三方客户端套壳别家内容
- 来路不明：号称免费不限量调用别家模型的、要输入账号密码的
- 用户看不懂的：推理框架、训练代码、论文复现、纯开发者基础设施
- 成人、加密货币、政治相关
- 只有一个 README 没有可用版本的（没有 release 也没有在线地址）

看过但决定不发的，写进已推荐清单的「看过但不发」，下次不再出现。

### 3 核对事实

```bash
python3 ~/.claude/skills/github-gems-cn/scripts/facts.py owner/repo owner/repo2
```

**帖子里每个数字都只能来自这个脚本的输出**：星数、上线天数、协议、各平台安装包大小、支持的平台。功能只写 README 里明确写了的，读 `readme_head`，不够就再读完整 README。

几条硬规矩：
- **「代码是 AI 写的」只在有出处时写**：`readme_says_ai_wrote_code` 有命中，或者作者自己的推文、博客说了。没有出处就不写
- 星数写约数：7.3 万星、1.3 万星、2100 星
- 大小写 Mac 安装包的大小，没有 Mac 版就写用户最可能用的平台
- 协议：MIT、Apache 2.0 直接写；GPL、AGPL、其他少见协议在文案里只说开源免费，在待实测里注一句二次开发有要求
- 项目还很早期的（版本 0.x、模板很少、README 自己说了还在开发）要在文案里老实说一句

### 4 写短推

格式照用户自己的样板：

```
第一行  一句话钩子，谁做了什么，叫什么名字（平替类直接说是谁的平替）
第二行  数字反差和功能清单，功能之间用顿号
（空一行）
第三行  一句对比或一句用法，让人想点开
```

要求：
- 每条按 X 的算法不超过 280（中文一个字算 2，链接算 23），写完用下面的检查算一遍，留余量控制在 250 以内
- 链接默认放首评（外链会降推荐）；用户要求放正文也可以，它算 23
- 守用户的写作规矩：不用 emoji，正文不用破折号、冒号引出的列表、箭头、引号、书名号、省略号、感叹号，不用 AI 常用句式（见 x-article-standard 第四节）
- 中文和英文、数字之间加空格
- 不写「求转发」「建议收藏」这类求互动的话

长度检查：

```bash
python3 -c "import sys,re;t=sys.argv[1];t=re.sub(r'https?://\S+','x'*23,t);print(sum(2 if ord(c)>0x2E7F else 1 for c in t))" "帖子全文"
```

### 5 交付

1. 在 `~/图文创作/01-项目/` 新建项目（工作台的 `create_project`，名字 `GitHub开源推荐-<主题或序号>`），把短推写进 `发布包.md`，格式见 `references/pack-template.md`
2. 每条写配图建议：首选自己装一遍录 20 秒屏；装不了的录 README 滚动或官网演示；不要直接搬别人的宣传视频
3. 写好的仓库加进 `~/图文创作/00-素材库/GitHub开源推荐/已推荐清单.md` 的「已写未发」；用户说发了，挪到「已发」并写日期
4. 回复里用两三句话说每条是什么、为什么选它，最后列出看过但没写的备选和不写的原因

## 用户的样板（Compositor，2026-10-03 发）

```
前苹果设计师靠 AI 手搓了一个 PS 平替，叫 Compositor。
7MB 大小，免费开源（MIT）。图层、蒙版、调色、内容识别填充全都有。

PS 几个 G，它只要 7MB，代码基本是 AI 写的。
github.com/robbietilton/Compositor
```

它好在三处：钩子里有人设反差（前苹果设计师、靠 AI），第二行全是硬数字和用户熟悉的功能名，第三行用 PS 几个 G 对比 7MB 把反差说透。写新帖时三处都要有对应的东西，找不到人设反差就用数字反差。
